Vim's editing grammar

A verb and a noun, composed as you type them. Most vim commands were never designed by anyone.

Eight verbs, fourteen nouns on this page, and every pairing works. Build one below, then use the sheet as a lookup. Press / to filter it.

what to do
Motion

Text object

8 operators × 14 nouns = 112 commands. Nobody implemented any of them individually.

Modes

Normal is home, not just the start. Every finished edit ends there.

NormalKeys run commands. Esc always returns here and is always safe.
InsertKeys insert text. Entered with i a o and friends.
Visualv characters, V lines, Ctrl-v block. Then press an operator.
Cmdline: command, / ? search. Enter runs it, Esc cancels.
Op-pendingAfter d c y, waiting for a noun. Neovim shows the pending keys bottom right.

Into insert mode

Pick the door that lands you where the edit is. A is the one you'll press most.

iBefore the cursor
aAfter the cursor. Exists because the cursor sits on a character, so i can't reach past the last one
IFirst non-blank of the line
AEnd of the line
oNew line below, correctly indented
ONew line above
giBack to wherever you last left insert mode

Getting unstuck

When confused, press Esc first and reason afterwards.

EscHome. Harmless in normal mode
Ctrl-[Byte-identical to Esc, and closer to your pinky
Ctrl-cMostly works, but skips hooks some plugins rely on
Ctrl-qUnfreezes the terminal after you hit Ctrl-s for "save". Not a vim problem
fgBrings nvim back after Ctrl-z suspended it
:q :q! :wQuit, quit discarding, write
ZZ :wqWrite and quit
:qa!Abandon everything, all files

Motions — inside a line

W B E to travel, w b e to operate. Aim f at a rare character, then correct with ;

w b e geBy word. Punctuation forms its own words, so w crosses spark.read.parquet( in seven presses
W B EBy WORD: whitespace-delimited only. Three presses for the same thing
0 ^Column zero / first non-blank. For indented code you want ^
$ g_End of line / last non-blank. $ will take trailing whitespace with it
f{c} F{c}Find forward / back, land on it
t{c} T{c}Till: land just before it. This is what makes ct( work
; ,Repeat the last f or t, same / opposite direction
3f"Counts work. Never crosses a line break

Motions — across the file

} is "next thing" at whatever granularity you already put blank lines at.

{ }Previous / next blank line. Boundary must be truly empty; two spaces and it sails past
%Matching bracket. If not on one, it scans forward on the line and jumps to that pair's match
gg GFirst / last line
42G :42Line 42. What you use when a stack trace hands you a number
H M LTop / middle / bottom of the screen, not the file
Ctrl-d Ctrl-uHalf screen down / up. Ctrl-f Ctrl-b for full
zz zt zbRedraw with the current line centred / at top / at bottom. Cursor stays put
/pat ?patSearch forward / back. It's a motion, so d/foo works
n NNext / previous match
* #Search for the word under the cursor. Whole words only; g* for loose
:nohClear the highlighting when it gets noisy

Operators

Doubling means the current line: dd yy cc >>. Two-letter ops double the last letter, so guu.

dDelete
cChange: delete, then insert mode
yYank. Also fills register 0
> <Indent / dedent. Always linewise
=Reindent by the filetype's rules. The fix for badly pasted code
gu gU g~Lowercase / uppercase / toggle case
gqReflow to the wrap width
gcComment out. Built into neovim 0.10+; vim needs a plugin
!Pipe through a shell command and replace with the output. !ip then sort or jq .

Text objects — pairs

i = the contents, a = plus the delimiters. Brackets work across lines; quotes never leave the line.

i( a(Parens. i) ib ab are the same thing
i{ a{Braces. iB aB are aliases. ci{ rewrites a whole dict from anywhere inside
i[ a[Square brackets
i< a<Angle brackets
i" a"Double-quoted string. Also i' and i`
it atXML / HTML tag pair
2i(Counts go outward a nesting level, not forward
vi( i( i(Repeating a pair object in visual mode expands the selection a level at a time

Text objects — shapes

No delimiters, so i and a split differently: i = the thing, a = plus the whitespace around it.

iw awWord. aw takes the trailing space so the gap closes; iw leaves it
iW aWWORD, whitespace-delimited
ip apBlock of non-blank lines. dap takes the blank line after, so spacing stays right
is asSentence. Fine for prose, near-useless in code
ciwThe rename you'll use most. Works from anywhere in the word, unlike cw
no if afVim has no object for a function, an argument, or an indented block. Treesitter adds them

One-key edits

Shortcuts for common operator-and-noun pairs.

dd yy ccWhole current line
D CSame as d$ and c$. C is how you rewrite the tail of a line
YNeovim maps it to y$; plain vim does yy. Check with :verbose nmap Y
x XDelete the character under / before the cursor
s SSubstitute character / whole line
r{c}Replace one character without entering insert mode
J gJJoin with the line below, with / without inserting a space
~Toggle case of one character

Repeat

Repeats the last change, not the last command. Motions don't count and don't reset it.

.Replay the last change. A whole insert session, i through Esc, counts as one
3.Replay with the count replaced by 3, not multiplied
A;<Esc> j.The positioning is part of the change, so it re-runs correctly on a line of a different length
/x ciw <Esc> n.Find-and-replace with you confirming each site
Ctrl-g uTyped in insert mode, ends the current change block and starts a new one
@:Repeat the last : command. Dot cannot reach ex commands
arrowsMoving the cursor mid-insert breaks the change in two, so . repeats only the tail. Don't

Undo

Undo is a tree, not a stack. A branch you undo is never destroyed.

u Ctrl-rUndo / redo one change. Same unit the dot repeats, which is why u wipes a whole typed paragraph
3uThree changes back
UUndo all recent changes on the last-changed line. Itself undoable
g- g+Back / forward in time, across every branch. This is how you reach the rewrite you abandoned
:undolistBranch points with timestamps
:earlier 10mRewind ten minutes. :later 30s goes forward
:earlier 5fBack five file writes. "Show me two saves ago" without touching git
:set undofilePersist the tree to disk. Off by default in both editors
:UndotreeVisual browser, built into neovim 0.12 after :packadd nvim.undotree

Registers

There is no clipboard, just 36 slots. yy then dd then p gives the wrong text, because both wrote to the same one.

"{r}{cmd}The prefix that names a register: "ayy, "ap, "ad}
""Unnamed. Every yank, delete and change writes here, which is the whole problem
"0Yanks only. Deletes never touch it, so "0p is "paste what I actually copied"
"_Black hole. "_dd deletes without stomping your yank
"1 – "9Delete ring, most recent first. After "1p, the dot increments the number
"-Small deletes, less than a line, so they don't flush the ring
"a – "zYours. Capital appends: "ayy then "Ayy collects scattered lines in order
"+ "*System clipboard / X11 primary. Same thing on macOS and Windows
"% ". ": "/Filename, last inserted text, last : command, last search pattern
"=Expression. "=strftime("%Y-%m-%d") then Enter then p
:regShow them all, with a type column: l, c or b

Paste

A register stores text and a shape. That's why a yy'd line always lands as a new line.

p PAfter / before the cursor, or below / above the line if the register is linewise
yyp yyPDuplicate the current line below / above
]p [pPaste linewise, reindenting to match the current line
gpPaste and leave the cursor after it, so gp gp gp stacks copies
v then PReplace a selection without clobbering the register, so it repeats. Use P, never p
Ctrl-r 0Paste a register from inside insert mode
Ctrl-r Ctrl-wOn the command line, inserts the word under the cursor. Stops you retyping identifiers

The two rules

Every noun carries both. Together they explain why dw, de and dj all behave differently.

linewisej k G gg H M L and any doubled operator. Whole lines, column discarded
characterwiseEverything horizontal: w e f $ % /
exclusiveStops before the character it lands on: w b 0 ^ { } / ?
inclusiveTakes it: e ge f F t T $ %
:help wPrints the word "exclusive" in the entry. Look it up rather than memorise the list

Deliberate exceptions

Documented, not bugs. Knowing they exist stops you doubting the grammar.

cwActs like ce on a word, so you don't retype the space you just ate. dw keeps the original behaviour
dwOn the last word of a line, stops at the line end instead of joining the next
. after vRepeats the size, not the meaning: same line count. dap repeats the intention
i( vs i"Quote objects seek forward on the line. Bracket objects don't seek at all
d}From at-or-before the first non-blank, the exclusive motion is promoted to linewise
}A "blank" line with whitespace on it is not a paragraph boundary. :set list to see

Prefix keys

g is a namespace, not an operator. Vim ran out of keys and opened a second page of the keyboard.

g z Ctrl-w [ ]The five shelves. Pressing one alone does nothing; it waits
gu gU g~ gq gcOperators living on the g shelf
gg ge g_ g* gj gkMotions. gj and gk move by display line, which matters in wrapped text
gv gi gf gx gJNeither: reselect, resume insert, open file under cursor, open URL, join without space
grn grr graLSP actions in recent neovim. If gr does something odd, that's why
:help gThe full index for a shelf. Also :help z, :help CTRL-W

Neovim vs vim

Everything above is identical in both. These are the differences you'll actually notice.

ConfigLua in init.lua. Neovim still reads vimscript
Defaultshlsearch, incsearch, matchit and a mode-shaped cursor all on. Vim leaves them off
gcComment operator built in since 0.10
YMapped to y$, finally matching D and C. Some distributions map it back
PasteBracketed paste is handled natively, so :set paste is unnecessary and deprecated
ClipboardNeeds an external provider. :checkhealth clipboard says which. Vim needs it compiled in: :echo has('clipboard')
SSHOSC 52 since 0.10, so "+y can reach your laptop's clipboard from a remote box
ObjectsTreesitter adds af, ac, aa for functions, classes and arguments. The strongest editing-only argument for neovim

Recall

Why does dw take the trailing space when cw does not?

w is exclusive and lands on the start of the next word, so the space in between falls inside the region.

cw should behave identically and deliberately does not. It acts like ce, because you are about to type a replacement and would otherwise retype the space. dw keeps the original behaviour, since deleting a word usually should close the gap.

You delete a five-line function with V4jd. The next one is seven lines. Why does . fail?

After a visual-mode operation, . repeats the size rather than the meaning: the same number of lines. So it takes five lines of a seven-line function.

dap instead. A noun names a region rather than measuring one, so the repeat re-evaluates it where the cursor now is.

You yy, navigate, dd, then p, and the wrong text appears. Name both fixes.

Yanks and deletes share the unnamed register, so the dd overwrote the yy.

After the fact: "0p, since register 0 only ever receives yanks. In advance: "_dd, which throws the delete into the black hole. The first gets used more, because you usually notice too late.

Nobody wrote code implementing >ip. Explain why it works.

> enters operator-pending mode, a real mode whose only job is to wait for something that answers "which region". ip answers it.

Because the halves are independent, one new text object gains every operator at once. That is why a plugin defining af immediately gives you daf, yaf, caf and gcaf.

i appears twice with unrelated meanings. Why is that not a conflict?

Meaning is resolved by mode. In normal mode i starts insert; after an operator it means "inner" and waits for an object.

Giving up the guarantee that a key does one fixed thing is exactly what lets fifty keys carry hundreds of meanings. It is also why Esc is the right reflex when confused: it puts you in a known state.
